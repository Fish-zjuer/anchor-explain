## 项目一句话

跨场景 AI 截图讲解系统：用户在文档上截取一块区域，系统捕获**带地址的结构化坐标**（不只是像素），AI 先尝试讲解，不够时按地址回取上下文，最终输出**带定位的讲解步骤**并逐步高亮流转。

核心命题：**截图 = 带地址的锚点，不是像素包。**

### 两个已知的"看起来像 bug"的现象

1. **高亮仍可能落在别的行**：现在 AI 自己决定 location，它可能讲错行——
   这是**模型质量问题**，不是接线问题。要看它有没有越界 → `smoke:chain` 里 §3.3 的越界会被判掉并重试一次。

## 关键约束速览（细节见 `CONTRACTS.md` / `DECISIONS.md`）

1. 两条线分工：线1 代码编辑器走 VS Code 原生高亮 + 流转；线2 PDF **只做框选定位，不做高亮流转**
2. `core/ prompts/ orchestrator/ adapters/` **零 `vscode` 依赖**，靠 `core/src/ports.ts` 抽象，保证可在 Node 里直接测
3. fork 是 `mathematic-inc/vscode-pdf`（**Apache-2.0**），须保留 LICENSE/NOTICE、写 `MODIFICATIONS.md`、**移除上游品牌字样**
4. PDF 框选用**注入式 overlay**，**不碰 `assets/pdf.js/`**（上游 pdf.js 是 vendored + 打补丁的）
5. 假货只允许出现在**最外层边界**，中间链路全真。**S3 起产物里已没有替身**（替身只在 `test/` 里）
6. 键位**只提供命令 + 默认键位**，默认不绑 Space，用户自选；状态栏提示读**用户实际绑定**
7. **验收是用户实操**：S1 / S2 / S3 各自确认后才进下一片
8. **`SourceAdapter.detect()` 是同步 `boolean`**（规范原文如此）。改成 `Promise` 属契约变更，须经用户确认。
9. **`node --test` 直接跑 `.ts`**（Node 24 类型剥离已可用，无需构建步骤）。测试脚本必须写成 `node --test "test/*.test.ts"`——传目录不行，Windows 下 shell 不展开通配符。
10. **产物一律 `dist/extension.cjs`**（CommonJS：宿主的 `require` 不吃 ESM 入口；包内 `type: module`，故用 `.cjs` 后缀）。`tsc` **只做类型检查、从不产 JS**。新增扩展往 `esbuild.mjs` 的 `TARGETS` 加一行，不另写打包脚本。
11. **提交前跑 `pnpm check`**（typecheck → test → build → smoke → smoke:chain）。
12. **`fakes/*` 不进 `@anchor/core` 的 barrel**，导入必须写成 `@anchor/core/fakes/fakeProvider`——多打一截路径就是防止正式链路悄悄依赖替身。**新增替身要同时加到 `packages/core/package.json` 的 `exports`**（漏了会报"找不到模块"，S3 踩过）。
13. **改 `test/fixtures/main.c` 第 40-48 行** → 必须同步 `fakes/fakeEditorPort.ts` 的 `FAKE_SELECTION_TEXT`、`fakes/fakeProvider.ts` 的脚本行号，**以及 `scripts/smoke-walkthrough.mjs` 里的 `EXPLANATION_JSON`**（S3 起链路冒烟的"模型输出"是它）。`test/fakes.test.ts` 有耦合锁拦前两个。
14. **`@types/vscode` 必须精确等于 `engines.vscode` 的**下界**（现为 `1.90.0`，不带 `^`）；`engines.vscode` 本身是范围 `^1.90.0`。** 不变式是"类型版本 = 范围下界"，不是"两个字段字符串相同"。见 `CONTRACTS.md` §9.5 / D39。
15. **仓库内文本一律 LF**（根 `.gitattributes` 钉死）。本机 `core.autocrlf=true`。见 D40。
16. **全仓测试数**：core 40 + ext 193 + pdf 12 = **245**（17 个测试文件，全部 vscode-free；线2 那个包另外还跑上游的 pdf.js 不变式守卫）。
17. **三个冒烟脚本分工不同**：`pnpm smoke`（**结构**：产物能加载、声明与注册对齐、webview 资源在不在、没有写文件的 API、**两个替身都已退出产物**，外加 **S8 起真跑一遍开始面板的宿主侧**）与 `pnpm smoke:chain`（**行为**：`capture` 从真选区跑到 decoration，**S3 起跑真编排循环**——只有 `globalThis.fetch` 是桩）与 `pnpm smoke:pdf`（线2）。断言条数：**73 + 122 + 67**。三者都**不替代 F5**。
18. **`commands.ts` 里没有任何替身了**（S1 有两处，S2 删假选区，S3 删假 AI）。新加替身要能说清"为什么只能在最外层边界"。
19. **侧边栏 CSS/客户端脚本是 TS 里的字符串常量**（内联进 webview，见 D42）。改 UI 必须同时想到：客户端脚本**不参与类型检查**，且 `ui/clientScript.ts` 里有一份 4 行的 `locationLabel` 副本。
20. **`decorationPlan.ts` 会过滤掉所有非 `CodeLocation`** —— 这是"PDF 上不出现任何高亮框"的结构性保证。
21. **步级底色与 emphasis 配色是两个独立 decoration type**（D41）。
22. **会话游标是「拍」不是「步」**（D48）：一个 step（n 个子高亮）占 n+1 拍，第 1 拍只铺整块底色，之后每拍点亮**一个**子高亮。**一次只亮一个点是"块底均匀"的结构性保证**，别改回"一次全亮"。
23. **`stop()` 必须先收状态、再清视觉**；`emit()` 必须先置 context key、三个渲染面各自 `isolated()`（D49）。回归测在 `smoke-walkthrough.mjs` 第 7、8 节。
24. **"讲解失败"与"渲染失败"不许混**（D49）：`startSession` 在 `explain()` 的 try **之外**。
25. **两个 context key 分工不许合并**（D46）：`walkthroughActive` 管推进键，`sessionOpen` 管收尾。`escape` 绑在后者上。
26. **webview 里的按键不会冒泡到工作台**（D47）：宿主把**已解析的用户键位**内联进 HTML（`ANCHOR_CHORDS`），客户端自己派发。状态栏提示与这份内联表必须同源（都来自 `keybindingResolve`）。
27. **侧边栏客户端脚本是字符串常量，不参与类型检查**，而且**里面不能出现反引号**（那是外层模板字符串的结束符）。DOM 行为仍靠 F5（已知缺口）。
28. **「整个文件」与「选区」是同一个形状**（D51）：`getDocumentSelection()` 返回的也是 `EditorSelection`，`capture(scope?)` 只按 `scope` 选来源。别为整文件另开一条产出路径。
29. **`sourceName` 走 `paths.ts` 的 `basenameOf()`**（D51），不要用 `node:path.basename`（按平台变行为），也不要用 `workspace.asRelativePath`（会把 vscode 拽进 `adapters/`）。
30. **`showState` 里的「上次捕获」不是调试残留**：真选区接上后，那是唯一能复核锚点区间的观测点，也是 `smoke:chain` 第 9 节的唯一观测点。
31. **写 `smoke-extension.mjs` 里的中文断言前先做 `\uXXXX` 反解**：esbuild 默认 `charset='ascii'`（`bundleText` 已在读取时解回来了）。
32. **§3.2 的两条实现约定不许改回去**（D52）：`file` 请求**没给 `path` 要放行**（§8 的 schema 里没有 `path`，当成"就要锚点这个文件"），且解析侧要把**自定义键一并带过去**。改回去会让 `file` 取件全部被拒——取件功能形同不存在，而且症状是"模型老是说取不到上下文"，很难往回追。
33. **去重排在频率前面**（D52）：两条规则同时命中时回灌已取内容，不回"已达上限"。§3.2 的编号是"规则序号"，不是"执行顺序"。
34. **输出校验是两道闸门**（D52）：编排层一道、命令层一道。别为了"省一次纯函数调用"删掉命令层那道 —— 渲染层只消费校验过的数据，这条规矩不该有例外。
35. **加新的 §6 配置项 = 改契约**：要同步 `CONTRACTS.md §6` + `package.json` 的 `contributes.configuration` + `config.ts` 的映射 + 单测。`temperature` 是这么加进去的。
36. **`temperature` 是"请求级优先于 provider 级"**（D52）：`ChatRequest.temperature ?? OpenAICompatibleOptions.temperature`。provider 实例是长命的，编排层可能想对某一轮单独降温。
37. **"不劫持"是两半的一件事**（D53）：`customEditors[0].priority = "option"` **加上**命令 `anchorPdf.openInAnchorViewer`。只写 `option` 而不给命令 = 用户根本进不来；只给命令而不写 `option` = 抢用户的默认打开方式。`smoke:pdf` 两半都断言。
38. **线2 的 `assets/` 与 `patches/` 是上游 vendored 源码，必须提交、绝不 ignore**（23MB，含 168 个 `.bcmap` / 10 个 `.pfb` / 4 个 `.wasm`）。本包另有一份 `.gitattributes` 把它们标成 `binary` —— 那些文件的字节偏移是算出来的，被换行转换动一个字节就会在某类 PDF 上炸。改 `.gitignore` 时别把 `dist/` 写回泛匹配（根文件里有注释说明）。
39. **线2 的 `tsconfig.json` 是全仓唯一的 `moduleResolution: "Bundler"` 例外**（D53 第 7 条）：上游源码的相对导入不带扩展名，改成 `NodeNext` 等于重写一遍 fork。别为了"统一"去改它。
40. **fork 的改动必须同步 `MODIFICATIONS.md`**（Apache-2.0 §4(b) 的义务，也是与上游对齐的唯一依据）。改 `src/` 里任何文件之前先看那份文件里"改动清单"有没有它；改完在那一节补一行。
41. **`pnpm --filter anchor-pdf test` 跑两件事**：`test/anchor.test.ts`（我们的几何/守卫单测）+ 上游的 `tools/check_pdfjs.mjs`（pdf.js 补丁的不变式）。将来升级 pdf.js 时**先看后者**——它红了就是补丁没打上，而不是 PDF 有问题。
42. **注入脚本（`media/anchor-select.js`）里不许写业务数学**（D54 第 2 条）：它不参与类型检查、也没法被单测，所以"落在第几页、占那一页的百分之几"必须留在 `src/anchor/rectToNormalizedBBox.ts`（有 11 条单测）。它只做"跟手的事"：画橡皮筋、报像素几何。
43. **`anchor:ready` 握手不许省**（D54 第 4 条）：用户点框选时页面可能还在加载，不握手就会丢消息，表现是"第一次点没反应，再点一次才行"。`smoke:pdf` 两条断言分别钉住"未握手不推"与"握手后补推"。
44. **宿主对框选结果优先用 `geometry` 重算**（D54 第 3 条），不要图省事直接用脚本给的 `bbox`：那等于让唯一有对错的换算由没有测试覆盖的代码定案。冒烟里专门喂了一个**错的** bbox 来钉这件事。
45. **"不画框"的结构性判据在 `smoke:pdf` 里**：它查线2 产物里**有没有** `TextEditorDecorationType` 这个 API。"线2 不做高亮流转"这条约束因此不是靠自觉。
46. **路径工具在 `@anchor/core`（`packages/core/src/paths.ts`）**：`normPath` / `samePath` / `basenameOf` / `countTextLines`。线1 的 `src/paths.ts` 只是转发（保留它是不想改十几个导入路径）。**新增代码直接从 `@anchor/core` 导入。**
47. **两条线的定位方式必须是两套**（D55 第 1 条）：`commands.ts` 的 `revealStep` 先看 `primaryLocationOf`（只对 `CodeLocation` 有值）走播放器，否则看 `isPDFLocation` 走 `anchorPdf.revealPage`。**PDF 那一句根本不经过播放器**，再叠上 `decorationPlan` 的过滤，"PDF 上不出现高亮框"是结构性的。
48. **`anchorPdf.revealPage` 只接收 `page`，且落到当前聚焦的面板**（D55 第 2 条）：`PDFLocation` 里没有路径字段，所以线1 报不出"该滚哪一份"；落到所有面板会让"同时开两份对比"时一起滚。
49. **`PDFLocation.filePath` 是可选的加法扩展**（D56 第 1 条）：线1 靠它去读文件取件与判页数。**读它的地方都要能退化**（S5/S6 造出来的老锚点没有它）。
50. **`pageCount` 的缺口已在 S7 关闭**（D56 第 7 条）：线1 无头打开 PDF 就有页数，`ctx.pageCount` 不再是 null，§3.3 的页码上界开始真的生效。
51. **`detect()` 明确不做**（D56 末段）：选适配器的依据是 `anchor.sourceType`（`commands.ts` 的 `adapterFor`），不是"环境适不适用"。§3.1 表里那一列判据降级为文档。**不要再"延期"它，也不要为了实现它去写一个没人调用的方法。**
52. **`rect.ts` 的 `intersectRects` 有三个消费者**（线2 的"落在哪一页"、"裁到页内"、线1 的"bbox 命中哪些文字块"）：它在 `@anchor/core`，**不相交返回 null 而不是零面积矩形** —— 后者会让"命中比例"变成除零。别在下游各写一份。
53. **打包第三方代码必须带署名**（D56 末段)：`pdfjsSource.ts` 顶部那条 `/*! ... */` 是**唯一**留在产物里的署名（esbuild 只保留 `/*!` 开头的注释），`smoke` 有断言守着。线1 产物因此从 468KB 涨到 **4.36MB**（pdf.js 本身就大；`pdfjs-dist` 是 ESM-only，CommonJS 产物没法 `require` 外部加载，所以只能打包）。
54. **`extractedText` 要在进模型之前补上**（D56 第 6 条）：PDF 锚点的 `bbox` 是地址，那一块里的文字才是模型第一批该看到的东西（`commands.ts` 的 `withPdfText`）。补失败一律静默忽略（扫描件没有文字层是正常情况）。
55. **固定按钮有四处入口、一处实现**（D57 第 1~2 条）：活动栏图标 / 面板 / 演练卡片 / `Ctrl+Alt+A`，全都只是 `executeCommand` 一条已声明的命令。**加一个动作 = `START_ACTIONS` 加一行 + `package.json` 里声明那条命令**（漏了声明有锁会红）。面板里不要写任何业务判断 —— 那不是风格问题，是这一片被验收的那件事。
56. **`start:run` 只回传 id**（D57 第 3 条）：`parseStartMessage` **只查形状**，成员资格由宿主 `findStartAction` 查。把成员资格塞进守卫，宿主那侧的查表就变成永远为真的死代码（`test/protocol.test.ts` 有一条锁钉着）。
57. **面板推快照、不推事件流**（D57 第 4 条）：**视图没被打开过时 `refresh()` 是空操作**，不许给它加"重放缓冲"——那是侧边栏（宿主建面板）才需要的东西。
58. **键位表是两张，各有各的镜像锁**（D57 第 6 条）：线1 `WALKTHROUGH_CHORDS` 对线1 的 `package.json`，线2 `LINE2_CHORDS` 对线2 的 `package.json`。面板显示线2 的键时也走同一套解析 —— **不许写死默认键**（那是替用户断言一件我们不知道的事）。
59. **同一句话只有一处**（D57 第 7~8 条）：状态词在 `protocol.ts` 的 `STATE_WORD`（状态栏与面板共用），"上次捕获"在 `describe.ts` 的 `captureSummary`（`Anchor: 显示状态` 与面板共用）。改文案时只改那一处。
60. **开始面板的客户端脚本与侧边栏同两条约束**：不许出现反引号与 `${`（否则是一次白屏）。**S8 起这是断言**（`test/startUi.test.ts` 遍历四份内联字符串），不再只是注释。
61. **门厅不许是死路**（D61/D62）：面板上每个灰按钮的 `note` 都必须**指出下一步按哪颗按钮**，而且那颗按钮真的存在、**真的能把事办完**（"没配 providers" → `anchorExplain.configure` 三个输入框写好，而不是"带你去看设置"）。**灰按钮只描述症状不指路，等于把这句提示变成废话。** 另：用户可见的通知文案走 `userFacing()`（不带错误码）；判断成败仍然一律用码。
62. **开始面板的动作要带参数时，参数写在命令里**（D61）：`start:run` 只回传 id（§5.5），面板说不出"带什么参数"；面板里也**不许**直接指向 VS Code 的内置命令 —— 那样"动作表里的命令必须在所属扩展里声明过"那条锁就守不住了（要包一层自己声明的命令）。
63. **`Anchor: 配置模型端点` 是唯一会写设置的地方**（D62），边界写死在 `CONTRACTS §6`：只写 `providers[id]` 的 `baseUrl`/`tier1Model`（别的字段与别的 provider 原样保留），必要时把 `activeProvider` 指过去，**永不写 `apiKey`**；合并读 `inspect().globalValue`（不是 `get()`，那会把工作区级的值复制进用户设置）。"产物里没有任何文档写入 API"那条断言不变 —— 禁止的是写**文档**，写自己的设置是另一回事。
64. **同一台阶卡两次就别再靠"讲清楚"**（D62）
65. **写设置的地方必须"验读"**（D63）：`update()` 在 `settings.json` 有语法错时会抛，**不接住就是"点了没反应"**；写完要**回读**，读不回来就明说失败（不许打印成功文案）。命令失败一律要说话（面板的 `runStartAction` 也接了 try/catch）。另：`providers`"少一层"（`{ baseUrl, tier1Model }`）能被 `looksFlattened()` 认出来并整理，provider id 只认**值是对象**的键 —— 否则字段名会被当成 provider 名，用户看到的提示全是错的。：这一步连续翻过两次车（没有入口 → 手写嵌套 JSON 把 `settings.json` 写坏）。判据是"用户要不要手写结构化数据"，要 → 就做成命令。
66. **讲解期间屏幕上必须有东西在动**（D64）：进度挂在**三处**（状态栏 / 通知（可取消）/ 开始面板那一行），因为**状态栏可以被用户关掉**（本机就关了：`workbench.statusBar.visible: false`）。取件记录同时是进度（`loggerOf` 的 sink 兼喂 `onPhase`）—— "AI 在背后操作却看不见"是焦虑的来源。**别把唯一的进度只放在一个可以被关掉的地方。**
67. **讲解风格是设置项，默认简约**（D65）：`anchorExplain.style` = `concise`（默认）/ `rigorous`。**两档 prompt 都必须写死"按数据怎么流组织步骤、不要从上到下一行一行地念"** —— 用户对第一版的原话是"太从上到下了，我希望能表达出数据流转的感觉"、"不要那么多名词什么的，要不还不如读代码本身了"。改 prompt 时这两句是**硬要求**，有单测钉着（`test/prompts.test.ts`）。
68. **给模型的"许可"必须出现在工具 schema 里**（D67）：模型唯一能看见的能力清单是 `tools` 的 `parameters` —— 把"可以读别的文件"只写进文档与系统提示，等于**许可不可执行**（模型没有点名文件这个参数，就不会去读）。同理，`required` 与 `description` 也是许可的一部分（"当前文档"这四个字就把范围锁死了）。
69. **同一条规则在两处判定时，两处的坐标必须一致，而且要有一条端到端断言**（D67）：S9a 的"允许集合"编排层收绝对路径、命令层从日志收**模型原样写的相对路径** —— 于是"读过又引用"被自己的闸门拦下，报错还说"这个文件没读过"（指的正是它刚读过的文件）。**凡是"两处各判一次"的设计（两道闸门、两个入口、两条线），先问它们的输入是不是同一套坐标。**
70. **prompt 的"允许/禁止"两句必须同口径，repair 与初次尤其要同口径**（D67）：输出契约那句"`filePath` 必须与锚点同一个文件"是 S1 时代的口径，跨文件后忘了改 —— 而它**同时被 repair 轮引用**，于是模型被拒之后拿到的修复提示又把它推向反方向，第二次注定失败。**repair 说错 = 修不回来。**
71. **"降级"不等于"静默"**（D67）：候选文件清单扫不出来、取件被拒、写设置失败……都可以降级继续，但**必须在用户能找到的地方留一句话**（输出通道「Anchor」），否则"空清单"与"真没有相关文件"、"没读到"与"读到了"在日志里长得一模一样，排查等于猜。
72. **一条消息的"发"和"收"要有一条端到端断言盯着，只测一端等于没测**（D68）：`tooltrace:append` 有协议类型、有客户端渲染、有重放缓冲 —— **唯独没有发送方**，于是那块 UI 永远写着"本次讲解没有请求额外上下文"，而它明明刚读了两个文件。**屏幕上说反话比不说话更坏**（用户会据此怀疑整个功能）。同理，凡是"宿主产生、webview 显示"的东西（快照、日志、进度），断言必须落在**收到的那一侧**。
73. **一次只许讲一份**（D68）：`explain` 有 `running` 护栏，重复按下明说一句然后不做。反面是"新的一次覆盖旧的一次"——同一处再花一份 token，而且先发的那份的通知会**滞留在屏幕上**直到它自己跑完（用户会以为卡住了）。 每次讲解的开始/结束/被忽略都往输出通道留一行（`讲解开始（第 N 次）` 等）—— 这样"屏幕上有滞留通知"与"开了两份"从日志里就能分开。
74. **跨文件之后，凡是提到"哪一段"的话都要带上文件名**（D68）：`1-60 这个区间已经取过了` 在单文件时代没有歧义，跨文件之后它既回灌给模型也显示给用户，含糊会把两边一起带偏。
75. **契约松了，消费它的人必须跟着松**（D69）：S9a 允许 `location` 落在别的文件里，而播放器"一拍 = 一个文件"的假设没跟着改 —— 于是 `protocol.h:16` 被画到 `main.c:16` 上，屏幕上出现一个**看起来很确定的假框**。**画错比不画更坏**：它是"屏幕在说反话"最硬的一种。凡是放宽一条契约，先把它的**全部消费者**找出来（渲染、标签、日志、进度）。
76. **一拍只画一个文件，焦点取最具体的那一个**（D69）：有子高亮就跟子高亮，否则跟步骤；其余文件的框这一拍不画，靠侧边栏标签指认。打开目标文件一律 `ViewColumn.One` + 预览标签 + `preserveFocus`（同组、不分屏、不堆积）。
78. **内联客户端脚本里一个反斜杠都不写**（D69）：它是**一个模板字符串**，源码里的反斜杠要写两个才等于运行时的一个 —— 少写一个就是语法错误，**整块面板白**，而且屏幕上不会有任何报错（脚本死了，"我死了"也印不出来）。去尾斜杠用字符类（/[/]+$/），反斜杠本身用 `String.fromCharCode(92)`；这个文件的注释里也不许出现反引号（会把字符串提前截断）。**改完必须过 `new Function(脚本)` 那条解析测试**（`test/sidebarClient.test.ts`，另有一份最小 DOM 跑行为；产物那一层在链式冒烟里再解析一遍）。
86. **"面板卡死"先看"讲完之后还留着哪些入口"**（D72，含键位那一半）：`上一步` / `退出` 的按钮**不许**被禁，`Alt+[`（prev）与 `Ctrl+Alt+W`（goto）的 `when` 必须是 `sessionOpen` 而**不是** `walkthroughActive` —— 讲完那一刻唯一还想做的两件事就是回看与退出；把"回看"这条路从按钮和键位上一起掐掉，用户看到的就是"按键、快捷键、按钮全不管用" —— 键盘（ESC / Alt+[）一直是好的，按钮比键盘小气就是自相矛盾，用户只会读成"面板死了"。**凡是"某个状态下所有操作都点不动"的面板，一律当死路处理**（D61 的同一条规矩）。
87. **按住不放不许变成连发**（D72）：`ev.repeat` 一律忽略。面板有焦点时自动重复会每次发一条 `ui:next` + 换拍 + 打开文件，把面板和编辑器一起压住 —— 那不是"快速推进"。
83. **单次取件默认 400 行、可调；超上限是"截断"不是"拒绝"**（D71）：`anchorExplain.maxFetchLines`（默认 400，上限 2000）。被拒的一轮是**白烧的预算** —— 用户在真机上 5 轮里 3 轮就这么没了。**但"关于这份文件的事实错误"仍然是拒绝**（`end` 超出文档总行数、PDF 的 maxSpan），因为说清事实比默默给它一段更有用。
84. **一个数只能有一个来源**（D71）：单次行数上限同时出现在**闸门**、**配置夹取**、**适配器声明的能力**与**提示词**里 —— 四处都指向 `DEFAULT_MAX_FETCH_LINES` / `MAX_FETCH_LINES_CEILING`。凡是"提示词里写死的数字"，先问它是不是别处也有一份（写死的 60 与闸门的 `maxSpan` 就是这么分家的）。
85. **`package.json` 里声明的设置必须真的被读到**（D71）：漏读不会报错、屏幕上也没有迹象，用户只会觉得"这个设置没用"。链式冒烟里有一条镜像锁盯着（声明 8 项 → 读取侧全被问到）。`style` 与 `fetchScope` 就静默失效过一整片（S8/S9a）。
79. **内联脚本里零反斜杠**（D70）：这条不变量现在有断言钉着（`test/sidebarClient.test.ts`）。两次栽跟头换来的 —— 少写一个反斜杠要么是**语法错误（面板全白、屏幕上没报错）**，要么是**静默切不开路径**（Windows 路径整条印进标签）。需要反斜杠时用 `String.fromCharCode(92)` 或字符类。
80. **面板脚本抛异常必须显示在面板上**（D70）：webview 里的异常**扩展侧收不到、屏幕上也不显示** —— 用户只看到"卡死"，我们两头都没有证据。所以消息处理外面有 try/catch，把第一行错因写成面板顶部的一条红字。
81. **播放器：同一文件不重复打开 + 渲染不并发堆积**（D70）：跨文件时焦点文件来回跳，每拍都 `showTextDocument` 会让预览标签反复重建（屏幕上持续抖动）。同一文件且已是活动编辑器就复用；堆积的渲染**只保留最后一拍**。
82. **异步渲染的断言必须先让它落定**（D70）：冒烟里那条 caveat 断言原来是在**上一拍的残留渲染**上通过的（会话已走到下一拍）。渲染是异步的 —— 断言前要 flush，否则测的是旧状态（与 D67 那条"端到端"是同一条教训）。
77. **不在锚点文件里的位置，标签必须带文件名**（D69）：`[第 16 行]` 在跨文件时代是有歧义的，用户就是这么被绕住的。`session:update` 因此带 `anchorPath`；**旧宿主不发就一律不标** —— 少说是可以的，标错不行。
88. **webview 里的 `acquireVsCodeApi()` 一个页面只能成功调一次**（D73）：第二次抛 `An instance of the VS Code API has already been acquired`（VS Code 1.137.0 预加载 `pre/index.html:209` 就是 `let acquired = false` + throw；只有 notebook renderer 与 chat 输出开了 `allowMultipleAPIAcquire`）。而 **PDF 页面里 pdf.js 自己要用它**（`viewer.mjs` 的 `VSCodeLinkService` 把链接交回宿主），且 `assets/main.mjs` 一开头就 import 了 viewer.mjs —— **它天然先跑到**。所以线2 的注入脚本必须：① 先接管 `globalThis.acquireVsCodeApi`、把实例共享出去（自己取一次，之后谁来取都给同一个；**装壳没验过就不取** —— 宁可我哑，也不能把 pdf.js 那次变成"第二次"、把页面链接全搞坏）；② `<script>` 排在 `pdf.mjs`/`main.mjs` **之前**（module 不带 `async` 时按文档顺序执行，这是结构性保证，不靠时序运气）。**违反的后果是静默的**：`postMessage` 全变空操作 → `anchor:ready` 发不出去 → 连十字光标都不出现，屏幕上没有任何字（用户原话"框选PDF，并没有反应"）。**一行 `catch { vscode = null }` 让整条链路哑了一整轮** —— 降级必须发声，没有通道就造一个（脚本在页面上贴故障说明；宿主在没握手时先说"还在加载"、再一次说"一直没有回应"+怎么查）。
89. **模板字符串里不许出现反引号**（D73 又栽一次）：`pdf-viewer-provider.ts` 里那段注入 HTML 是**一个模板字符串**，注释里写 `` `名字` `` 会把字符串当场截断 —— 报错长得像"缺少 )"，与那行真正的原因（引号）隔了好几行。D69 那条是给内联脚本定的，现在扩到"任何模板字符串"：**要强调就用「」**。构建会拦住它（`pnpm build` 直接失败），所以别绕过构建跑冒烟。
90. **注入脚本的行为也得有夹具**（D73）：`media/anchor-select.js` 既不进类型检查、也不进 bundle，改它以前只能靠 F5 手拖 —— 结果它哑了一整轮没人知道。现在 `test/anchorSelectClient.test.ts` 用**最小 DOM + 逐字复刻 VS Code 预加载语义的 `acquireVsCodeApi`**（含那条报错原文）把整条链路跑一遍。**复刻对方语义时要把出处写进注释**（版本 + 文件路径 + 行号），否则夹具会随时间变成童话。
91. **测试跑源码、用户跑产物 —— 凡"打包后才会出现的差异"，锁必须打在打包之后**（D74）：`import.meta.url` 会被 esbuild 改写成产物路径，于是 pdf.js 去 `dist/pdf.worker.mjs` 找它的 worker（`Setting up fake worker failed`），而 `node --test` 全绿 —— **S7 的 PDF 取件因此在用户手上从来没成功过**。同类差异还有：动态 import 的说明符、tree-shaking（字体/图标/字符串变体）、charset、相对路径。线1 冒烟里那条"用同一套打包选项把 `scripts/pdf-open-probe.mjs` 打成 cjs 再真的打开一份 PDF"就是这条规矩的落点。**锁红了先想清楚它守的是什么，别顺手删**（D74 里那条"没有文档写入 API"的锁被 pdf.js 的 XFA 枚举名 `TextEdit` 误报了，正确做法是把模式改成按**调用形状**扫，不是删掉它）。
92. **pdf.js 在产物里必须自己挂 worker**（D74）：`disableWorker: true` 只是"不用线程"，pdf.js 仍要把 worker 代码加载进主线程（默认靠 `import(GlobalWorkerOptions.workerSrc)`，那个值由 pdf.js 自己的 `import.meta.url` 推出）。所以 `pdfjsSource.ts` 里 `await import('pdfjs-dist/legacy/build/pdf.worker.mjs')` 后挂到 `globalThis.pdfjsWorker`（`legacy/build/pdf.mjs:22948` 读它）。说明符必须是**字面量**，esbuild 才会一起打包 —— 产物因此自洽，不依赖 `node_modules` 在旁边。代价：dev 产物 4.5MB → 13.4MB（惰性求值）。
93. **喂字节，不要给 pdf.js `url:`**（D75）：pdf.js 的 `url` 参数**只在浏览器环境成立**（`getUrlProp` 要拿 `window.location`），而它那句 `isNodeJS` 判定里有一个为 Electron **渲染进程**写的条件 —— VS Code 的扩展宿主是 Electron 的 **utility** 进程（`process.versions.electron` 有值、`process.type === 'utility'`），会被误判成"浏览器"，于是 `ReferenceError: window is not defined`。字节由注入的 `PdfBytesPort` 读（真实现 `fileSystemPort` = `workspace.fs`，对 remote/虚拟文件系统成立；`node:fs` 在那种工作区里会静默读到空）。**不要去掰 `isNodeJS`**：要么动 `process.versions`（影响整个宿主），要么依赖 pdf.js 内部判定，两个都不该由我们改。
94. **给 pdf.js 的字节必须是真正的 `Uint8Array`**（D75）：它明确拒绝 Node 的 `Buffer`（`Please provide binary data as Uint8Array, rather than Buffer.`），而 `node:fs` 给的正是 Buffer。端口是注入的，所以归一化放在入口（`Uint8Array.from` 复制一份：换掉 Buffer 身份，也避开 Node 小块内存池共享 ArrayBuffer 而 pdf.js 会 transfer 它）。
95. **"在我这儿是对的"必须先问"我这儿是什么形状"**（D73/D74/D75 是同一教训的三层）：D73 我以为它会说话（其实 `catch` 成了静默）；D74 我以为测过了（其实测的是源码，不是产物）；**D75 我以为环境一样（其实是干净的 CLI Node，宿主是 Electron 的 utility 进程）**。锁的三条要求：**跑产物、跑在宿主的形状里、并且验证过它能红**（`scripts/pdf-open-probe.mjs` 就是这三条的落点 —— 它自己打包、自己伪装成宿主，红过两次：一次 worker 找不到，一次 `window is not defined`）。
96. **PDF 上允许出现的东西只有三样，且都有明确的"何时消失"**（约束 1 收窄，D76）：① 框选模式的橡皮筋（按住指针期间）；② 拿不到 VS Code API 时的故障说明（不退隐）；③ **用户点了某一步时闪现的那个框（约 2 秒后自动摘掉）**。**不许常驻、不许自己冒出来** —— 播放/推进时一个框都没有（链式冒烟有断言）。要加第四样之前先问："它什么时候消失？"
97. **跨扩展新增能力要查对端声明再调**（D76）：两条线各自安装（D27），"装了线2"不等于"线2 是新版"。对着旧版调新命令会抛 `command ... not found`（对用户毫无意义）。判据用对端 `packageJSON.contributes.commands`：有就闪、没有就退回老行为，**并且两条路都要有冒烟断言**。
98. **成功路径也要有回执**（D76）：点某一步若目标就在当前页，画面上什么都不动 —— 看起来就是"没反应"。现在状态栏会说一句「已定位到第 N 页…」。D61~D73 那条"失败必须发声"的规矩，第一次用在**成功但看不出动静**的事上。
99. **"渲染成功"不等于"用户看得见"**（D77）：`visibleTextEditors` 里的编辑器**不是**一块可以随便往里画的画布 —— `setDecorations` 会画在用户没看的标签上（屏幕上看不见），`revealRange` 对**非活动编辑器什么都不做**（不滚、也不切过去）。凡是"我要让用户看到 X"的代码，先问一句：**它此刻在前台吗？** 播放器里这条判据落在 `#ensureEditor`：同一文件且**已是活动编辑器**才走捷径，否则把目标切到前台（复用已有 document，不重建预览标签 —— 那是 D70 要消掉的抖动）。`smoke:fileswitch` 用一条不变量钉着：**整条链路里没有任何一次 reveal 落在非活动编辑器上**。
100. **异步 API 的"生效"与"可见"是两件事**（D77）：这条与 85（"在我这儿是什么形状"）是一对 —— 那次问的是"环境形状一样吗"，这次问的是"**生效的位置，是用户在看的位置吗**"。改完必须验它能红：拿掉 `#focus` 那 3 条立刻红并指名 `wasActive=false`。
101. **"文件被关"不等于"用户要结束"**（D78）：VS Code 的**预览标签会被下一个预览替换掉**，而这会触发 `onDidCloseTextDocument` —— 于是**"讲进第二个文件"这个动作本身**就会关掉第一个文件的标签（常常就是锚点文件自己）。这条订阅在两种情况下的回调**一模一样**，唯一区别是**下一刻那个文件还在不在可见编辑器里**。所以判据不是"哪个文件被关了"，而是**"关完之后还有没有得讲"**：`onDidCloseTextDocument` 里只记 `pendingAnchorClose`，等 `onDidChangeVisibleTextEditors` 时再看一眼锚点文件可不可见 —— 可见 = 讲解继续，不可见 = 才 `stop()`。**不许在 close 回调里当场 `stop()`**（D78 第一版就是这么修的，照样误杀）。
102. **等异步动作做完，要找它自己的完成信号，不要拿时间来代替**（D78）：预览替换是"关旧的 + 开新的"连着做的一件事，`onDidChangeVisibleTextEditors` 是它**语义上**的完成信号；`setTimeout` 等的是一个猜出来的毫秒数，慢机器上早退、快机器上白等。
103. **护栏必须朝"会红"的那个方向写**（D78）：第 8b 节的第一版写的是"关掉 `protocol.h`（当前步所在文件）不许停"，而旧判据**也不** stop —— 于是它恒绿、什么都没测出来。写回归测先问一句：**"如果 bug 还在，这条断言会不会红？"** 答不上来就是没写对。同时，一条护栏若把"该继续"写进去了，就必须**另有一条把"该停"也写进去** —— 否则"永远不停"这种退化实现也能过。
104. **桩里新增的订阅必须在 `activate` 期间就存在**（D78）：`scripts/*.mjs` 的 vscode 桩漏了 `window.onDidChangeVisibleTextEditors`，而它是在 `activate` 里订阅的 —— 桩一缺，`activate` 当场抛，**整份扩展根本没装上**（而不是某条断言红）。往 `registerCommands` 里加新订阅时，两份桩（`smoke-walkthrough` / `smoke-extension`）都要补。

105. **可选的输入不能做成必答**（D79）：「重点讲什么」这类补充信息，跳过必须与老行为**一字不差**（跳过时 prompt 里不能多出那一节）。所以 Esc（`undefined`）与「回车但没打字」（`''`）合成同一个结果 —— 对用户来说"没写"就是一件事。另外：**Esc 在这里不取消讲解**，取消的入口是上一步那个确认框；同一个键在相邻两个框里含义不同，用户按错一次就丢掉刚选好的段。
106. **进了 prompt 的用户输入，屏幕上必须留得下痕迹**（D79/D80）：写好那句话之后，用户唯一能复核"它生效没"的地方是屏幕，而 prompt 里的东西本来就看不见。所以凡是用户写下的、选出的东西，都要进 `captureSummary()` —— 它是"说给用户听的一句话"的唯一格式化处，面板与「显示状态」两处便自动一致（D19 那句"两处各写一遍会分家"）。多段同理：`location` 只是**并集的外框**，只显示外框等于替用户改写了他选的范围。
107. **同一个"第 N 个"在所有界面必须指同一个东西**（D80）：队列那一行列出的第 1 段、可以点掉的那个清单里的第 1 段、发给模型时标了号的第 1 段 —— 三处各自排一遍的话，用户点掉"第 1 段"删掉的是模型眼里的第 2 段。**不报错、不崩，只是讲错了地方**。所以排序比较器只有 core 里那一个（`compareSegments`），队列加完**当场**就排，而不是等到 merge 时才排。
108. **给模型的多段原文必须标号，并明说"段之间的行没被选中"**（D80）：连成一坨的原文会被模型读成"这是一段完整代码"，于是它去讲那些用户没选过的行。这与 D69 是同一条规矩的两种形态：**屏幕上写给用户看的位置说明，一句都不能比模型看到的少**（D69 那次漏的是文件名，这次漏的是"哪几段被选中"）。
109. **多段限制在同一个文件里，而且要早点说清楚**（D80）：一次讲解只有一个锚点文件（D78 的收尾判据、"这次讲解到头了"的判据都按一个锚点文件写的）。用户在另一个文件里选新的一段时，给「清空 / 取消」二选一 —— 他此刻的意图几乎肯定是"我改盯另一个文件了"，现在就说清，比攒了四五段之后在最后一步报错损失小得多。
110. **"按钮有反应"不等于"用户收到了反馈"**（D81）：判据是**提示出现在他此刻在看的地方吗**，不是"我们发过一条提示"。这一条里发过的提示有三处（状态栏 3 秒临时消息、面板最下面那一行、按钮自身的按下态），而用户的原话是"虽然有反应，但是没有文本什么的提示" —— 因为**前两处他都没在看，第三处他会读成"就是没反应"**。所以"持续可见"的那一份必须放在**离他刚点的东西最近的地方**：分组标题挂数量（就在按钮正上方）、状态栏一个常驻计数（滚都不用滚）。连按两次导致队列里出现两段同样的范围，正是"以为第一次没生效"的直接后果。
111. **红的不一定是产品，先看返回值对不对**（D81 的实测教训）：写完 D81 的冒烟后 9 条断言全红，而打出来的值**看起来完全正确**（`已加入第 40-48 行 —— 队列里现在有 1 段`）。查下来是冒烟里被插重了一段、两段的期望值串了线。**看到红先分三档**：① 期望写错（最常见）② 桩与真实语义不一致 ③ 产品真错。三档的处理完全不同，而"直接去改产品"是其中最贵的一种。
112. **护栏要能"走对方向"才算存在 —— 而这次的证明来自一次操作失误**（D82）：D82 的判据改完之后第一次跑冒烟**忘了重新打包**，跑的还是旧 `dist`，那一次恰好就是 `FAIL D82 … session:end 次数 8 → 9`；换上新的 `dist` 才转绿。**"旧代码 → 红 / 新代码 → 绿"这一对实测值**比任何"我觉得它应该能测出来"都硬。所以：**改完源码必须 `pnpm build` 再跑冒烟**（见下面「这台机器上的操作注意」），而且看到冒烟红/绿时要先确认跑的是哪一份产物。
113. **判据里不许依赖"某个东西会自己回来"**（D82）：D78 的收尾判据写着"推迟一拍再看锚点文件还在不在 —— 播放器会把它又打开"，而**播放器只开当前这一拍的焦点文件**，从来没有把它打开过。护栏之所以是绿的，是因为桩**手动**把锚点文件放回了可见列表 —— 桩照着注释里的假设写，于是把假设一起验证成了"事实"。**换判据的方向是"换掉问题"，不是"更小心地猜同一个问题"**：从"锚点文件还在吗"换成"这次讲解还有没有落脚点"，轮换那条路就自然免疫了（因为轮换必然把新文件留在屏幕上）。
114. **一个功能如果会花用户的钱，它的"不花钱版本"必须单独成一颗按钮**（D83）："重放上次讲解"（不碰网络、结果逐字相同）与"重新讲一遍"（再问一次模型、会得到另一种讲法）代价差一个数量级，而中文里"重新讲"两件事都指得上。**合并它们等于替用户决定要不要再花一次钱。**基于同一个理由，验证"重放"必须断**模型调用次数为 0**，而不是断"面板上出现了文字" —— 后者在"其实是又问了模型一遍"时同样成立（D79 那段死代码就是被同一类断言放过去的）。
115. **跨重启活着的数据，读的时候要当外部输入**（D83）：`workspaceState` 里的存档可能是**上一个版本的我们**写的，也可能被用户手改坏。所以它带 `version`，对不上就**丢掉**而不是尽力兼容；坏掉**一个子高亮**只丢那一个（配色是装饰性字段，与 §3.3 同一条），**一个 step 都不剩**才整份作废。**读不出来一律当"没有存档"**，绝不抛 —— 它可能是命令的第一跳，一个坏档不该让整条链路炸掉。
116. **判屏幕之前先问"这瞬间是不是我们自己造成的"**（D84）：预览标签的轮换是"先关旧的、再开新的"两件异步的事，中间有一帧什么都没有 —— 那一帧与"用户把文件都关了"**长得一样**。所以判据不许读某一瞬间的样子就下结论，要能区分"这一帧是不是我们自己换文件换出来的"：播放器给出 `switching` / `onDidSettle`，宿主在 `switching` 期间**推迟**判定（且**不消费**立案标记，消费了就再也没机会判了）。另一条同源：记"关过文件"这个立案标记时，要问**这个文件与本次讲解有没有关系**（`sessionFiles()`），否则用户随手关一个无关标签，会借后来任意一次可见性变化**在别处**引爆。"**什么时候允许判**"和"**判什么**"是两件事，都要写对。顺带：桩里新增的 API 命名空间必须与**真实 API** 一致（这次栽在 `window.openTextDocument` vs `workspace.openTextDocument`）—— 桩写错时那条路**静默不跑**，冒烟会变成"**比真实更绿**"（与约束 111 / 112 同一条纪律）。

## 这台机器上的操作注意（不是产品问题，是干活方式）

1. **`bash` 在这台机器上是坏的**（`dirname: command not found` / `head`、`wc` 都没有）：
   走 PowerShell。这不影响 `pnpm check` —— 它自己会用对的解释器。
2. **PowerShell 的 stdout 不会回显到我这边的工具结果里**（退出码会）。所以看输出只有一条路：
   **先 `Out-File` 到文件，再用 Read 读回来**。中文会以 UTF-8 落盘，读回来是正常中文；
   直接读 stdout 看到的是 `鉁?` 这种乱码。
3. 于是**每一轮排查都会在仓库根目录留一堆 `.tmp-*.txt`**。它们一律是垃圾，收工时删掉：
   `Set-Location <仓库根>; Remove-Item -Path ".\\.tmp-*.txt" -Force`
   （注意：`Remove-Item -Filter ".tmp-*.txt"` **一条都删不掉**，还返回成功 —— 用 `-Path` 带通配符）。
   `.gitignore` 里也加了 `.tmp-*.txt` / `.tmp-*.json`。**别拿 `.tmp-*.txt` 存任何还要看的东西**。
4. **PowerShell 里的相对路径要当心**：`Set-Location` 到子目录之后，`..\x.txt` 落在**上一级的那个**目录，
   不是仓库根。写文件用绝对路径，省得回头找不到。
5. **单独跑冒烟之前必须 `pnpm build`**：`scripts/smoke-*.mjs` 加载的是
   `packages/*/dist/*.cjs`，**不是源码**。改了源码直接 `node scripts/smoke-walkthrough.mjs`，
   跑的仍是上一次打包的旧产物 —— 结果是"新写的断言红/绿都不可信"。
   **D82 那条护栏的"能红"就是这么偶然得到的**（旧产物红、新产物绿），
   但反过来也很容易骗人：改完源码忘了打包，看到全绿就以为改对了。
   要么用 `pnpm check`（它自己先 build），要么 `pnpm build && node scripts/smoke-*.mjs`。
