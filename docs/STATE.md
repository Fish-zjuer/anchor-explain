## 项目一句话

跨场景 AI 截图讲解系统：用户在文档上截取一块区域，系统捕获**带地址的结构化坐标**（不只是像素），AI 先尝试讲解，不够时按地址回取上下文，最终输出**带定位的讲解步骤**并逐步高亮流转。

核心命题：**截图 = 带地址的锚点，不是像素包。**

43. **`anchor:ready` 握手不许省**（D54 第 4 条）：用户点框选时页面可能还在加载，不握手就会丢消息，表现是"第一次点没反应，再点一次才行"。`smoke:pdf` 两条断言分别钉住"未握手不推"与"握手后补推"。

47. **两条线的定位方式必须是两套**（D55 第 1 条）：`commands.ts` 的 `revealStep` 先看 `primaryLocationOf`（只对 `CodeLocation` 有值）走播放器，否则看 `isPDFLocation` 走 `anchorPdf.revealPage`。**PDF 那一句根本不经过播放器**，再叠上 `decorationPlan` 的过滤，"PDF 上不出现高亮框"是结构性的。
48. **`anchorPdf.revealPage` 只接收 `page`，且落到当前聚焦的面板**（D55 第 2 条）：`PDFLocation` 里没有路径字段，所以线1 报不出"该滚哪一份"；落到所有面板会让"同时开两份对比"时一起滚。
49. **`PDFLocation.filePath` 是可选的加法扩展**（D56 第 1 条）：线1 靠它去读文件取件与判页数。**读它的地方都要能退化**（S5/S6 造出来的老锚点没有它）。
50. **`pageCount` 的缺口已在 S7 关闭**（D56 第 7 条）：线1 无头打开 PDF 就有页数，`ctx.pageCount` 不再是 null，§3.3 的页码上界开始真的生效。
51. **`detect()` 明确不做**（D56 末段）：选适配器的依据是 `anchor.sourceType`（`commands.ts` 的 `adapterFor`），不是"环境适不适用"。§3.1 表里那一列判据降级为文档。**不要再"延期"它，也不要为了实现它去写一个没人调用的方法。**
52. **`rect.ts` 的 `intersectRects` 有三个消费者**（线2 的"落在哪一页"、"裁到页内"、线1 的"bbox 命中哪些文字块"）：它在 `@anchor/core`，**不相交返回 null 而不是零面积矩形** —— 后者会让"命中比例"变成除零。别在下游各写一份。
53. **打包第三方代码必须带署名**（D56 末段)：`pdfjsSource.ts` 顶部那条 `/*! ... */` 是**唯一**留在产物里的署名（esbuild 只保留 `/*!` 开头的注释），`smoke` 有断言守着。线1 产物因此从 468KB 涨到 **4.36MB**（pdf.js 本身就大；`pdfjs-dist` 是 ESM-only，CommonJS 产物没法 `require` 外部加载，所以只能打包）。
54. **`extractedText` 要在进模型之前补上**（D56 第 6 条）：PDF 锚点的 `bbox` 是地址，那一块里的文字才是模型第一批该看到的东西（`commands.ts` 的 `withPdfText`）。补失败一律静默忽略（扫描件没有文字层是正常情况）。
55. **固定按钮有四处入口、一处实现**（D57 第 1~2 条）：活动栏图标 / 面板 / 演练卡片 / `Ctrl+Alt+A`，全都只是 `executeCommand` 一条已声明的命令。**加一个动作 = `START_ACTIONS` 加一行 + `package.json` 里声明那条命令**（漏了声明有锁会红）。面板里不要写任何业务判断 —— 那不是风格问题，是这一片被验收的那件事。
56. **`start:run` 只回传 id**（D57 第 3 条）：`parseStartMessage` **只查形状**，成员资格由宿主 `findStartAction` 查。把成员资格塞进守卫，宿主那侧的查表就变成永远为真的死代码（`test/protocol.test.ts` 有一条锁钉着）。
57. **面板推快照、不推事件流**（D57 第 4 条）：**视图没被打开过时 `refresh()` 是空操作**，不许给它加"重放缓冲"——那是侧边栏（宿主建面板）才需要的东西。
58. **键位表是两张，各有各的镜像锁**（D57 第 6 条）：线1 `WALKTHROUGH_CHORDS` 对线1 的 `package.json`，线2 `LINE2_CHORDS` 对线2 的 `package.json`。面板显示线2 的键时也走同一套解析 —— **不许写死默认键**（那是替用户断言一件我们不知道的事）。
59. **同一句话只有一处**（D57 第 7~8 条）：状态词在 `protocol.ts` 的 `STATE_WORD`（状态栏与面板共用），"上次捕获"在 `describe.ts` 的 `captureSummary`（`Anchor: 显示状态` 与面板共用）。改文案时只改那一处。
60. **开始面板的客户端脚本与侧边栏同两条约束**：不许出现反引号与 `${`（否则是一次白屏）。**S8 起这是断言**（`test/startUi.test.ts` 遍历四份内联字符串），不再只是注释。
61. **门厅不许是死路**（D61/D62）：面板上每个灰按钮的 `note` 都必须**指出下一步按哪颗按钮**，而且那颗按钮真的存在、**真的能把事办完**（"没配 providers" → `anchorExplain.configure` 三个输入框写好，而不是"带你去看设置"）。**灰按钮只描述症状不指路，等于把这句提示变成废话。** 另：用户可见的通知文案走 `userFacing()`（不带错误码）；判断成败仍然一律用码。
62. **开始面板的动作要带参数时，参数写在命令里**（D61）：`start:run` 只回传 id（§5.5），面板说不出"带什么参数"；面板里也**不许**直接指向 VS Code 的内置命令 —— 那样"动作表里的命令必须在所属扩展里声明过"那条锁就守不住了（要包一层自己声明的命令）。
63. **`Anchor: 配置模型端点` 是唯一会写设置的地方**（D62），边界写死在 `CONTRACTS §6`：只写 `providers[id]` 的 `baseUrl`/`tier1Model`（别的字段与别的 provider 原样保留），必要时把 `activeProvider` 指过去，**永不写 `apiKey`**；合并读 `inspect().globalValue`（不是 `get()`，那会把工作区级的值复制进用户设置）。"产物里没有任何文档写入 API"那条断言不变 —— 禁止的是写**文档**，写自己的设置是另一回事。
64. **同一台阶卡两次就别再靠"讲清楚"**（D62）
65. **写设置的地方必须"验读"**（D63）：`update()` 在 `settings.json` 有语法错时会抛，**不接住就是"点了没反应"**；写完要**回读**，读不回来就明说失败（不许打印成功文案）。命令失败一律要说话（面板的 `runStartAction` 也接了 try/catch）。另：`providers`"少一层"（`{ baseUrl, tier1Model }`）能被 `looksFlattened()` 认出来并整理，provider id 只认**值是对象**的键 —— 否则字段名会被当成 provider 名，用户看到的提示全是错的。：这一步连续翻过两次车（没有入口 → 手写嵌套 JSON 把 `settings.json` 写坏）。判据是"用户要不要手写结构化数据"，要 → 就做成命令。
66. **讲解期间屏幕上必须有东西在动**（D64）：进度挂在**三处**（状态栏 / 通知（可取消）/ 开始面板那一行），因为**状态栏可以被用户关掉**（本机就关了：`workbench.statusBar.visible: false`）。取件记录同时是进度（`loggerOf` 的 sink 兼喂 `onPhase`）—— "AI 在背后操作却看不见"是焦虑的来源。**别把唯一的进度只放在一个可以被关掉的地方。**
67. **讲解风格是设置项，默认简约**（D65）：`anchorExplain.style` = `concise`（默认）/ `rigorous`。**两档 prompt 都必须写死"按数据怎么流组织步骤、不要从上到下一行一行地念"** —— 用户对第一版的原话是"太从上到下了，我希望能表达出数据流转的感觉"、"不要那么多名词什么的，要不还不如读代码本身了"。改 prompt 时这两句是**硬要求**，有单测钉着（`test/prompts.test.ts`）。
68. **给模型的"许可"必须出现在工具 schema 里**（D67）：模型唯一能看见的能力清单是 `tools` 的 `parameters` —— 把"可以读别的文件"只写进文档与系统提示，等于**许可不可执行**（模型没有点名文件这个参数，就不会去读）。同理，`required` 与 `description` 也是许可的一部分（"当前文档"这四个字就把范围锁死了）。
69. **同一条规则在两处判定时，两处的坐标必须一致，而且要有一条端到端断言**（D67）：S9a 的"允许集合"编排层收绝对路径、命令层从日志收**模型原样写的相对路径** —— 于是"读过又引用"被自己的闸门拦下，报错还说"这个文件没读过"（指的正是它刚读过的文件）。**凡是"两处各判一次"的设计（两道闸门、两个入口、两条线），先问它们的输入是不是同一套坐标。**
70. **prompt 的"允许/禁止"两句必须同口径，repair 与初次尤其要同口径**（D67）：输出契约那句"`filePath` 必须与锚点同一个文件"是 S1 时代的口径，跨文件后忘了改 —— 而它**同时被 repair 轮引用**，于是模型被拒之后拿到的修复提示又把它推向反方向，第二次注定失败。**repair 说错 = 修不回来。**
71. **"降级"不等于"静默"**（D67）：候选文件清单扫不出来、取件被拒、写设置失败……都可以降级继续，但**必须在用户能找到的地方留一句话**（输出通道「Anchor」），否则"空清单"与"真没有相关文件"、"没读到"与"读到了"在日志里长得一模一样，排查等于猜。
72. **一条消息的"发"和"收"要有一条端到端断言盯着，只测一端等于没测**（D68）：`tooltrace:append` 有协议类型、有客户端渲染、有重放缓冲 —— **唯独没有发送方**，于是那块 UI 永远写着"本次讲解没有请求额外上下文"，而它明明刚读了两个文件。**屏幕上说反话比不说话更坏**（用户会据此怀疑整个功能）。同理，凡是"宿主产生、webview 显示"的东西（快照、日志、进度），断言必须落在**收到的那一侧**。
73. **一次只许讲一份**（D68）：`explain` 有 `running` 护栏，重复按下明说一句然后不做。反面是"新的一次覆盖旧的一次"——同一处再花一份 token，而且先发的那份的通知会**滞留在屏幕上**直到它自己跑完（用户会以为卡住了）。 每次讲解的开始/结束/被忽略都往输出通道留一行（`讲解开始（第 N 次）` 等）—— 这样"屏幕上有滞留通知"与"开了两份"从日志里就能分开。
74. **跨文件之后，凡是提到"哪一段"的话都要带上文件名**（D68）：`1-60 这个区间已经取过了` 在单文件时代没有歧义，跨文件之后它既回灌给模型也显示给用户，含糊会把两边一起带偏。
75. **契约松了，消费它的人必须跟着松**（D69）：S9a 允许 `location` 落在别的文件里，而播放器"一拍 = 一个文件"的假设没跟着改 —— 于是 `protocol.h:16` 被画到 `main.c:16` 上，屏幕上出现一个**看起来很确定的假框**。**画错比不画更坏**：它是"屏幕在说反话"最硬的一种。凡是放宽一条契约，先把它的**全部消费者**找出来（渲染、标签、日志、进度）。
76. **一拍只画一个文件，焦点取最具体的那一个**（D69）：有子高亮就跟子高亮，否则跟步骤；其余文件的框这一拍不画，靠侧边栏标签指认。打开目标文件一律 `ViewColumn.One` + 预览标签 + `preserveFocus`（同组、不分屏、不堆积）。
78. **内联客户端脚本里一个反斜杠都不写**（D69）：它是**一个模板字符串**，源码里的反斜杠要写两个才等于运行时的一个 —— 少写一个就是语法错误，**整块面板白**，而且屏幕上不会有任何报错（脚本死了，"我死了"也印不出来）。去尾斜杠用字符类（/[/]+$/），反斜杠本身用 `String.fromCharCode(92)`；这个文件的注释里也不许出现反引号（会把字符串提前截断）。**改完必须过 `new Function(脚本)` 那条解析测试**（`test/sidebarClient.test.ts`，另有一份最小 DOM 跑行为；产物那一层在链式冒烟里再解析一遍）。
86. **"面板卡死"先看"讲完之后还留着哪些入口"**（D72，含键位那一半）：`上一步` / `退出` 的按钮**不许**被禁，`Alt+[`（prev）与 `Ctrl+Alt+W`（goto）的 `when` 必须是 `sessionOpen` 而**不是** `walkthroughActive` —— 讲完那一刻唯一还想做的两件事就是回看与退出；把"回看"这条路从按钮和键位上一起掐掉，用户看到的就是"按键、快捷键、按钮全不管用" —— 键盘（ESC / Alt+[）一直是好的，按钮比键盘小气就是自相矛盾，用户只会读成"面板死了"。**凡是"某个状态下所有操作都点不动"的面板，一律当死路处理**（D61 的同一条规矩）。
87. **按住不放不许变成连发**（D72）：`ev.repeat` 一律忽略。面板有焦点时自动重复会每次发一条 `ui:next` + 换拍 + 打开文件，把面板和编辑器一起压住 —— 那不是"快速推进"。
83. **单次取件默认 400 行、可调；超上限是"截断"不是"拒绝"**（D71）：`anchorExplain.maxFetchLines`（默认 400，上限 2000）。被拒的一轮是**白烧的预算** —— 用户在真机上 5 轮里 3 轮就这么没了。**但"关于这份文件的事实错误"仍然是拒绝**（`end` 超出文档总行数、PDF 的 maxSpan），因为说清事实比默默给它一段更有用。
84. **一个数只能有一个来源**（D71）：单次行数上限同时出现在**闸门**、**配置夹取**、**适配器声明的能力**与**提示词**里 —— 四处都指向 `DEFAULT_MAX_FETCH_LINES` / `MAX_FETCH_LINES_CEILING`。凡是"提示词里写死的数字"，先问它是不是别处也有一份（写死的 60 与闸门的 `maxSpan` 就是这么分家的）。
85. **`package.json` 里声明的设置必须真的被读到**（D71）：漏读不会报错、屏幕上也没有迹象，用户只会觉得"这个设置没用"。链式冒烟里有一条镜像锁盯着（声明 8 项 → 读取侧全被问到）。`style` 与 `fetchScope` 就静默失效过一整片（S8/S9a）。
79. **内联脚本里零反斜杠**（D70）：这条不变量现在有断言钉着（`test/sidebarClient.test.ts`）。两次栽跟头换来的 —— 少写一个反斜杠要么是**语法错误（面板全白、屏幕上没报错）**，要么是**静默切不开路径**（Windows 路径整条印进标签）。需要反斜杠时用 `String.fromCharCode(92)` 或字符类。
80. **面板脚本抛异常必须显示在面板上**（D70）：webview 里的异常**扩展侧收不到、屏幕上也不显示** —— 用户只看到"卡死"，我们两头都没有证据。所以消息处理外面有 try/catch，把第一行错因写成面板顶部的一条红字。
81. **播放器：同一文件不重复打开 + 渲染不并发堆积**（D70）：跨文件时焦点文件来回跳，每拍都 `showTextDocument` 会让预览标签反复重建（屏幕上持续抖动）。同一文件且已是活动编辑器就复用；堆积的渲染**只保留最后一拍**。
82. **异步渲染的断言必须先让它落定**（D70）：冒烟里那条 caveat 断言原来是在**上一拍的残留渲染**上通过的（会话已走到下一拍）。渲染是异步的 —— 断言前要 flush，否则测的是旧状态（与 D67 那条"端到端"是同一条教训）。
77. **不在锚点文件里的位置，标签必须带文件名**（D69）：`[第 16 行]` 在跨文件时代是有歧义的，用户就是这么被绕住的。`session:update` 因此带 `anchorPath`；**旧宿主不发就一律不标** —— 少说是可以的，标错不行。
